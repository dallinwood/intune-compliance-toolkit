# mSCP Import (Plan 1 of 2) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the CIS-PDF pipeline with an importer that vendors a pinned mSCP release under `sources/mscp/` and generates a normalized, schema-validated macOS rule library under `baselines/` for the web UI.

**Architecture:** `tools/mscp_fetch.py` downloads a release tag tarball and copies a fixed subset of `src/mscp/data/` into `sources/mscp/upstream/` byte for byte, recording the tag and commit in `sources/mscp/source.json`. `tools/mscp_normalize.py` is pure functions turning one mSCP rule (YAML dict) into one v3 rule plus its index entry. `tools/import_mscp.py` is the one-command CLI that runs both stages, writes into a temp directory, validates with `tools/validate_library.py`, and only then swaps the result into `baselines/`.

**Tech Stack:** Python 3.14 (repo `.venv`), PyYAML 6.0.3, jsonschema 4.26.0, pytest 9.1.1, stdlib `urllib`/`tarfile`.

**Spec:** `docs/plans/2026-10-20-mscp-source-design.md` (sections 3, 4, 7, 8). Plan 2 (web UI, generator, attribution, deploy) is written after this plan lands, against the real generated data.

## Global Constraints

- Rule content comes only from mSCP. Nothing reads `baseline-references/` or any CIS document.
- Generated files are never hand-edited; they are only regenerated by `tools/import_mscp.py`.
- Rule ids are `mscp.<upstream rule id>`, never sequential numbers.
- `--tag` is required for a fetch; there is no "latest" default. First target tag: `release_27.0`.
- Output is byte-stable: `json.dumps(value, indent=2, sort_keys=True, ensure_ascii=False) + "\n"`, written with `newline="\n"`, rules processed in sorted path order.
- Any unrecognised upstream shape is an error (non-zero exit, `baselines/` untouched), never a silent skip.
- The importer refuses any text containing `Vendor Description` (Apple content excluded from mSCP's CC BY 4.0 grant).
- The upstream copy is read from `src/mscp/data/` inside the tarball; the top-level `rules`/`baselines`/`schema` symlinks are ignored.
- Work stays on `macos-compliance-framework-rebase`. Commit and push after each task (per `.claude/CLAUDE.md`), trailer `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. No force-push, rebase or branch deletion.
- No em dash characters (U+2014) anywhere, code or prose.
- Licence constants (used verbatim): name `CC BY 4.0`, url `https://creativecommons.org/licenses/by/4.0/`, rights holder `NIST macOS Security Compliance Project contributors`, repository `https://github.com/usnistgov/macos_security`.

## Review Focus

- YAML 1.1 implicit floats: reference ids like `8.10` load as the float `8.1` under `yaml.safe_load`; 206 of 350 macOS rules in `release_27.0` change if floats are parsed. Expected: every reference string survives exactly. Pinned in Task 3.
- Windows line-ending conversion (`core.autocrlf=true` on the maintainer's machine): vendored files must stay byte-identical to upstream and generated JSON must stay LF. Pinned by `.gitattributes` in Task 1 and the drift test in Task 6.
- Hostile or odd tarball members: symlinks, hard links, `..` paths, absolute paths. Expected: never written, never followed. Pinned in Task 4.
- A failing import halfway through. Expected: `baselines/` and `sources/mscp/` exactly as before. Pinned in Task 5.
- Re-running the import on unchanged upstream data. Expected: zero diff. Pinned in Tasks 5 and 6.

v3 rule shape (all keys required; nullable where shown):

```json
{
  "schema_version": 3,
  "id": "mscp.os_gatekeeper_enable",
  "platform": "macOS",
  "title": "Enable Gatekeeper",
  "discussion": "Gatekeeper _MUST_ be enabled. ...",
  "source": {
    "name": "mscp",
    "release_tag": "release_27.0",
    "commit_sha": "<40 hex>",
    "upstream_rule_id": "os_gatekeeper_enable",
    "upstream_path": "rules/os/os_gatekeeper_enable.yaml",
    "upstream_url": "https://github.com/usnistgov/macos_security/blob/<sha>/src/mscp/data/rules/os/os_gatekeeper_enable.yaml",
    "license": { "name": "CC BY 4.0", "url": "https://creativecommons.org/licenses/by/4.0/", "rights_holder": "NIST macOS Security Compliance Project contributors", "modified": true }
  },
  "assessment": { "status": "automated", "manual_reason": null },
  "architecture": null,
  "applicability": { "26.0": [ { "name": "cis_lvl1", "severity": null }, { "name": "disa_stig", "severity": "high" } ] },
  "tags": ["800-53r5_low", "cisv8"],
  "references": { "nist": { "800-53r5": ["CM-14"] } },
  "check": {
    "default": { "shell": "...", "result": { "type": "string", "value": "PASS" } },
    "by_version": { "15.0": { "shell": "...", "result": { "type": "integer", "value": 1 } } }
  },
  "odv": null,
  "remediation": {
    "default": { "shell": null, "additional_info": null },
    "by_version": {},
    "mobileconfig_info": null,
    "mobileconfig_by_version": {},
    "ddm_info": null
  }
}
```

Constraints the schema enforces: `id` pattern `^mscp\.[a-z0-9_]+$`; `assessment.status` enum `automated|manual`; `manual_reason` enum `manual|inherent|permanent|n_a|supplemental|no_check` and `null` exactly when status is `automated`; `architecture` enum `arm64|i386|null`; version keys pattern `^\d+\.\d+$`; `result.type` enum `integer|string|base64`; `result.value` is integer, string, or the literal `"$ODV"`; `check` is `null` or has `default` (nullable) and `by_version`; `odv` is `null` or `{datatype: number|string|enum, description: string, validation: object|null, recommended, by_benchmark: object}`; `references`, `mobileconfig_info`, `ddm_info` are opaque (object/array/null).

Index entry: `{ id, title, file, assessment, architecture, applicability, tags, has_odv }` with `file` relative to the index's folder (e.g. `rules/os_gatekeeper_enable.json`). Index file: `{ "schema_version": 3, "source": "mscp", "rules": [...] }`.

Manifest: `{ "schema_version": 3, "sources": [ { name, display_name, release_tag, commit_sha, retrieved_date (YYYY-MM-DD), repository_url, license, index_path, rule_count } ] }`.

Mapping rules for `normalize_rule` (mSCP field -> v3):
- Version keys are keys of `platforms.macOS` matching `^\d+\.\d+$`. `applicability[v]` = that version's `benchmarks` as `{name, severity}` (`severity` null when absent), `[]` when it has none.
- `check.default` from `platforms.macOS.enforcement_info.check`; `check.by_version[v]` from `platforms.macOS[v].enforcement_info.check`. `check` is `null` when neither exists. `result` must have exactly one key among `integer|string|base64`; an `integer` value that is a string must be exactly `"$ODV"`. Anything else raises.
- `remediation.default` from `enforcement_info.fix` (`shell`, `additional_info`, each null when absent); `remediation.by_version` likewise; `mobileconfig_info`/`ddm_info` copied as-is; `mobileconfig_by_version[v]` from a version's `mobileconfig_info`.
- `assessment`: `manual_reason` = first tag in `MANUAL_TAG_PRIORITY` present (`not_applicable` maps to `n_a`), else `supplemental` if the upstream id starts with `supplemental`, else `no_check` if `check` is null, else status `automated`.
- `architecture` from tags `arm64`/`i386`; both present raises.
- `odv` from upstream `odv`: `datatype`/`description`/`validation` from `hint` (`validation` null when absent; datatype outside `number|string|enum` raises); `recommended`; `by_benchmark` = every other key whose name appears in any macOS `applicability` list. `$ODV` anywhere in `check` without an `odv` block raises.
- `tags` sorted; `references` copied as-is.
- Any string anywhere in the upstream rule containing `Vendor Description` raises.
- Unknown keys under `platforms.macOS` other than version keys, `enforcement_info`, `introduced` raise.

## Notes for Plan 2

Findings from the final whole-branch review that Plan 2 (web UI, script generator, attribution, deploy) must account for:

- **Version applicability, revisiting design section 6.** "Fall back to `default` for any other version" is wrong for real data. `os_messages_app_disable_familycontrols` is automated but has a null `check.default` (checks for 15.0 and 26.0 only). 28 rules have no 27.0 key, several of them deliberately replaced by 27.0-only rules. The generator must treat "a macOS version this release knows, with the rule absent" as not applicable, and only use `default` for versions newer than the import. That needs a covered-versions list in the data.
- **Benchmark catalogue.** Tag-based baselines (800-53, 800-171, CMMC, cisv8, ...) mean "tag AND version key", not tag alone (the bare 800-171 tag overcounts mSCP's baseline by 20 rules).
