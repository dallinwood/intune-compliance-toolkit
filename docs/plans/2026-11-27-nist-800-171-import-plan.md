# NIST SP 800-171 Import Plan

Date: 2026-11-27
Status: Implemented 2026-11-27 (the decisions in section 2 were made without the maintainer and await review)

**Goal:** Import the 97 current NIST SP 800-171 Rev. 3 security requirements from NIST's OSCAL (oscal-content `v1.6.0`) as a rule source, show them in the web UI, and generate a `supports` mapping from each mSCP rule to the 800-171 requirements mSCP itself cites.

**Pattern:** the same as the NIST SP 800-53 source (`2026-11-11-nist-800-53-source-design.md`, `2026-11-11-nist-800-53-import-plan.md`). Where this plan is silent, follow those documents.

## 1. Facts about the upstream (checked 2026-11-27)

- **Releases carrying 800-171.** oscal-content has eight releases (`v1.0.0` to `v1.6.0`). 800-171 first appears in `v1.4.0`; all three releases that carry it hold Rev. 3 only (Rev. 2 is not in the repository).
- **No framework change between them.** `v1.4.0` (OSCAL content version `1.0.0`) has 29 requirements with empty statement text; `v1.5.0` (`1.1.0`) fills them in, and NIST's own revision remark calls it "a bug fix for empty statements in security requirements". No statement wording changed and no requirement was added or removed. `v1.5.0` to `v1.6.0` is identical requirement content, an OSCAL format bump only (`v1.2.2` to `v1.2.3`).
- **File:** `nist.gov/SP800-171/rev3/json/NIST_SP800-171_rev3_catalog.json`. There is no `nist.gov/SP800-171/README.md`; only the repository `LICENSE.md` is vendored with it.
- **Shape (`v1.6.0`):** 17 groups (`class: family`, ids `SP_800_171_03.01`..., `sort-id` `03.01`, label `Access Control (03.01)`), 130 entries (`class: requirement`, ids `SP_800_171_03.01.01`, no nesting), 33 of them withdrawn (`status: withdrawn`, `incorporated_into` / `addressed_by` links, no parts). Each current requirement has one `statement` (29 prose only, 68 with `item` parts up to two levels) and one `guidance` part, plus `assessment-objective` / `assessment-method` parts (ignored, as for 800-53).
- **Item labels** are full ids: `SR-03.01.01.a`, nested `SR-03.01.01.c.01`.
- **Parameters:** 85 with `label`, `usage`, `guidelines`, `props`; 3 with `select` plus the fixed label `SELECTED PARAMETER VALUES`. 182 `{{ insert: param, ... }}` expressions, none in guidance. No Markdown `](#...)` links.
- **References:** 356 `reference` links to back-matter resources. 157 point to resources titled with an SP 800-53 control (`AC-02`, `AC-02(03)`) whose link is NIST's CPRT page for that control in 800-53 5.1.1: these are 800-171's source controls. The other 199 are supporting publications.
- **Version:** `metadata.version` (`1.1.0`) versions NIST's OSCAL file, not the framework. The CPRT property `framework-version-identifier` is `SP_800_171_3_0_0`.

## 2. Decisions (made without the maintainer, open to review)

1. **One release, `v1.6.0`.** The maintainer asked for history only where the framework changed; it never did. `v1.4.0` is skipped as an OSCAL bug release, `v1.5.0` as a re-publish of the same content.
2. **Release label `3.0.0`**, derived from `framework-version-identifier` (`SP_800_171_<major>_<minor>_<patch>`), not `metadata.version`. The import fails if the property is missing or another shape.
3. **Source** `nist_800_171`, display name `NIST SP 800-171 Rev. 3`, vocabulary label `NIST SP 800-171`.
4. **Rule ids** `nist_800_171.<requirement number>` (`nist_800_171.03.01.08`); rule files `rules/03.01.08.json`; `upstream_rule_id` is the OSCAL id (`SP_800_171_03.01.08`). The id part must match `^03\.\d{2}\.\d{2}$`.
5. **Title** is the requirement title (`Unsuccessful Logon Attempts`). **Section path** is one level, `<family sort-id> <family title>` (`03.01 Access Control`), so families sort in NIST's order.
6. **Discussion** is Markdown: `## Requirement`, the statement, `## Discussion`, the guidance. Item labels are rendered as the publication prints them, derived from the OSCAL label: `SR-<number>.a` becomes `a.`, `SR-<number>.a.01` becomes `1.`; any other shape fails the import. Parameters render like 800-53 (`[Assignment: organization-defined number]`, `[Selection (one or more): ...]`).
7. **References:** `source_controls` holds the 800-53 control labels exactly as NIST writes them (`AC-02(03)`), `publications` the other resource titles. A resource titled like a control whose link is not a CPRT SP 800-53 page fails the import.
8. **No benchmarks.** 800-171 has no baselines; every rule has one applicability entry with no target, version or benchmarks. Every rule is manual (`no_check`).
9. **Withdrawn requirements** are not rules, as for 800-53.
10. **Shared OSCAL rendering.** The generic parts of the 800-53 normalizer (parameter inserts, link rewriting, item lists, property and key checks) move to `tools/nist_oscal.py` and both normalizers use them. 800-53 output must stay byte-identical (`python tools/import_nist_800_53.py --offline` leaves `git status` clean).
11. **Mapping.** The mSCP to 800-53 generator is generalised to a list of citation targets; 800-171 is a second target reading `references.nist["800-171r3"]` (citation `03.03.08` resolves to `nist_800_171.03.03.08`). It writes `baselines/_mappings/rules/mscp-to-nist-800-171.json` and `docs/mappings/mscp-to-nist-800-171-unresolved.json`. The mSCP importer regenerates both mappings; each NIST importer regenerates its own. The 800-53 mapping and report must stay byte-identical.
12. **Not in scope:** Rev. 2, SP 800-172, assessment objectives, CMMC. (An 800-171 to 800-53 mapping from the source controls was first out of scope and was added afterwards at the maintainer's request; see decision 13.)
13. **800-171 to 800-53 mapping** (maintainer's call, 2026-11-27): `related`, one way, stored as NIST states it (each requirement to its source controls); the reverse is indexed automatically, and 800-53 has no references to 800-171. The links point at the current 800-53 release (`v1.6.0`, 5.2.0) although NIST published the source controls against 5.1.1, because the control ids carry over; the note on every link says so. `related` links do not count towards coverage.

## 3. Tasks

### Task 1: Normalize and import 800-171 `v1.6.0`

- Extract `tools/nist_oscal.py` from `tools/nist_800_53_normalize.py`; confirm the 800-53 offline import is byte-identical and its tests pass unchanged.
- Add `tools/nist_800_171_normalize.py`, `tools/nist_800_171_fetch.py`, `tools/import_nist_800_171.py`, with tests and a small hand-written fixture catalog under `tests/fixtures/nist_800_171/`.
- Import `v1.6.0`; vendored files under `sources/nist_800_171/releases/v1.6.0/upstream/`; `.gitattributes`, NOTICE and README updated.
- Tier: full Python suite (importer, shared module, regenerated data).

### Task 2: Show 800-171 in the web UI

- Vocabulary source label; any pinned counts in Vitest/e2e that change because 97 rules are added; a new `webui/e2e/nist-800-171.spec.ts` (source filter, a requirement's details with nested items and an assignment).
- Screenshots at about 375px and 1280px of the filtered Rules view and an expanded requirement, read before committing.

### Task 3: Generate the mSCP to 800-171 mapping

- Generalise the generator (decision 11), wire the hooks, add tests, commit the generated mapping and report, README "Mapping rules" section.
- e2e: an mSCP rule shows its 800-171 links and a 800-171 requirement shows the mSCP rules that support it.
